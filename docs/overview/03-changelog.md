# 3. Change Log

## v2.0 — thay đổi so với bản gốc
| # | Thay đổi | Ảnh hưởng |
|---|---|---|
| 1 | Thanh toán online dùng **SePay thật** (VietQR/Open Banking), xác nhận qua **Webhook** thay cho "sandbox payment" mô phỏng. | payment-service, order flow, checkout saga, notification |
| 2 | Cập nhật 3 điểm quan trọng: admin scope (có account user), auth đầy đủ, thuật ngữ payment → SePay. | business, product |
| 3 | **Admin self-protection**: không tự khóa/xóa/hạ quyền; bảo vệ admin cuối cùng. | auth-service |
| 4 | Chuẩn hóa **API versioning** `/api/v1/...`, `/internal/v1/...`. | toàn bộ API, gateway, frontend |
| 5 | Bổ sung **Order State Machine** chặn admin cập nhật trạng thái không hợp lệ. | order-service |
| 6 | Định nghĩa **Checkout orchestration + Saga**; saga cơ bản đưa vào Sprint 3. | order-service, roadmap |
| 7 | Làm rõ **ranh giới auth-service ↔ user-service** (Identity vs Profile) + lazy-init. | auth-service, user-service |
| 8 | Hoàn thiện catalog: category conflict guard, Cloudinary image metadata/upload, variant wiring và product-first public listing không dùng dữ liệu giả. | product-service, frontend |
| 9 | Add Product chuyển sang guided flow; product mới mặc định INACTIVE, chỉ ACTIVE khi có variant và chặn xóa final variant của ACTIVE product. | product-service, frontend, docs |
| 10 | Admin Product Management hiển thị lỗi thân thiện, field guidance và recovery action; recoverable errors giữ nguyên drawer/form, image upload failure là partial success. | frontend, docs |
| 11 | Customer Shop category filter hiển thị **toàn bộ category thật** (gồm cả con) từ `GET /api/v1/categories`; endpoint public không param nay trả danh sách phẳng thay vì chỉ root. "Tất cả" là option FE để clear filter; không hardcode category. | product-service, frontend, docs |
| 12 | Admin Product Management: friendly error message dịch sang tiếng Việt; lỗi variant (add/update/delete, `LAST_ACTIVE_VARIANT`, duplicate SKU) hiển thị inline trong khu vực Variants của Edit Product drawer thay vì chỉ hiện toast; xóa variant/product/category dùng dialog xác nhận theo style dự án thay cho `window.confirm`/`window.alert`. | frontend, docs |
| 13 | Admin Category Management: Gateway dedupe thêm `Access-Control-Expose-Headers`/`Vary` (cùng nhóm với `Access-Control-Allow-Origin/Credentials` đã dedupe trước đó) để tránh CORS response header bị trùng lặp giữa Gateway và product-service; create/update/delete category có thông báo lỗi thân thiện tiếng Việt riêng khi không phải lỗi nghiệp vụ đã biết (`CATEGORY_IN_USE`/`CATEGORY_HAS_CHILDREN`/`SLUG_EXISTS`). | api-gateway, frontend, docs |
| 14 | Chuẩn hóa xác nhận/lỗi trên toàn bộ Admin Dashboard: thêm `AdminConfirmDialog` dùng chung, thay `window.confirm` cuối cùng còn lại (xóa tài khoản User Management) và bổ sung xác nhận cho vô hiệu hóa tài khoản, đổi trạng thái đơn hàng, gửi lại thông báo, tạo AI index job; lỗi self-protection/last-admin/invalid-transition/retry hiển thị inline cạnh action/row thay vì chỉ toast; thêm `admin-error-messages.js` chuẩn hóa 401/403/network sang tiếng Việt cho các trang chưa có helper riêng. | frontend, docs |
| 15 | Fix product image upload trả 500 chung chung khi Cloudinary chưa có credential: `ProductService.uploadImage` kiểm tra `ProductImageStorage.isConfigured()` trước, trả `IMAGE_STORAGE_NOT_CONFIGURED` (503) rõ ràng thay vì để exception rơi vào `IMAGE_UPLOAD_FAILED` (500); log lỗi upload thật sự nay gồm filename/content-type/size/loại exception (không log secret). Frontend có message riêng cho `IMAGE_STORAGE_NOT_CONFIGURED` trong khu vực Images. | product-service, frontend, docs |
| 16 | product-service tự nạp `BE/.env` khi chạy local từ IntelliJ (profile `local`), vì IntelliJ không tự source `.env` như `docker compose`. Ban đầu dùng `LocalDotenvEnvironmentPostProcessor` tự viết; sau đổi sang cơ chế chuẩn của Spring Boot `spring.config.import: optional:file:../.env[.properties]` trong `application-local.yml` — đơn giản hơn, không cần class Java riêng. Biến thật (OS env/system property/docker-compose) luôn có priority cao hơn, không bao giờ bị ghi đè; thiếu `.env` vẫn khởi động bình thường. Log chỉ ghi presence boolean + folder, không ghi giá trị secret. | product-service, docs |
| 17 | Fix cart hiển thị "Product"/"$0"/"One Size · Default" sau khi add-to-cart: `CartService.buildCartResponse` trước đây không bao giờ gọi lại product-service để lấy `variant`, nên `CartItemResponse.variant` luôn `null` và subtotal luôn `0`. Nay mỗi item được enrich qua `GET /internal/v1/products/variants/{variantId}` (tên/size/color/material/ảnh/giá hiệu lực); item không còn tồn tại hoặc không `ACTIVE` được đánh dấu `available: false` + `unavailableMessage` thay vì hiện giá giả; `totalAmount` tính đúng `unitPrice × quantity` (trước đây cộng dồn unitPrice mà bỏ sót quantity). Frontend tách `cart.mapper.js` khỏi `cart.api.js` để test được, hiển thị material khi có và trạng thái "không còn khả dụng" cho item mất. Checkout/order-service không đổi — vẫn tự lấy giá authoritative từ product-service khi tạo order. | cart-service, frontend, docs |

Chi tiết kỹ thuật của mục 4–8 nằm trong thư mục `architecture/` và `decisions/`.
